# Tests that are unrunnable on a given major FOR A CORRECT REASON, and the reason.
#
# WHY THIS FILE EXISTS. The vacuity layer exits EXIT_INCOMPLETE when anything in
# the run declared itself unrunnable, because an unrunnable test must not leave a
# run green. That is right, and it makes every major below 18 exit non-zero on a
# corpus with nothing wrong with it: `pgcolumnar.analyze()` writes through
# `pg_restore_attribute_stats` and `WITHOUT OVERLAPS` both arrived in PostgreSQL
# 18. Six tests decline on 15, 16 and 17 for that reason alone.
#
# So the rule is sharpened rather than masked: an UNEXPECTEDLY unrunnable test
# must not leave the run green. A test listed here for the running major may
# decline; anything else may not, and a test listed here that RUNS is refused
# too, because a feature arriving is a fact this file should stop claiming.
#
# It is the same move `--pgc-expect-tests` made for the collected count, which
# exists because "pytest exits 0 having collected nothing" was the same kind of
# silent pass. Proposed by @OffgridwithJD reviewing #1163, whose matrix could not
# land without it.
#
# FORMAT: major<space>nodeid. Comments and blank lines are ignored. A major with
# no rows expects nothing to decline, which is what 18 and 19 claim.
